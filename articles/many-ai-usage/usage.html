S-01 · 3-minute guide

many-ai-usage
の使い方

複数の AI サブスクの残枠を、1画面で。使うサービスの usage ページを一度だけ教えれば、あとはブラウザ内でまとめて確認できます。

ページの HTML・Cookie・トークンを外部 AI やサーバーへ送ることはありません。

Chrome: 審査中（近日公開） Chrome版 ZIP → Firefox: 審査中（近日公開） Firefox版 XPI → GitHub →

3分で分かる 3ステップ

拡張を入れる公開前は GitHub Releases の ZIP / XPI を使えます。
usage ページを開くログイン済みのサービスで、残枠が見える画面へ進みます。
数字を1回教える残枠をクリックして保存。以降は同じ場所を自動で読み取ります。

S-02 · Practice

teach-mode 練習場

実サイトへ行く前に、変化するサンプルを使って「複数の数字を1セッションで教える」流れを試せます。

拡張が入っていないと動きません。 この練習場は many-ai-usage の teach-mode で読み取るためのページです。
Chrome ストア審査中 Chrome版 ZIP Firefox AMO 審査中 Firefox版 XPI
Chromeへ手動で入れる
  1. ZIPを保存して展開します。
  2. chrome://extensions を開き、「デベロッパー モード」を有効にします。
  3. 「パッケージ化されていない拡張機能を読み込む」で、展開したフォルダーを選びます。
Firefoxで一時的に試す
  1. about:debugging#/runtime/this-firefox を開きます。
  2. 「一時的なアドオンを読み込む」から、XPIまたは展開後の manifest.json を選びます。
  3. 一時アドオンはFirefox終了時に外れます。恒久利用はAMO公開後のストア版を使ってください。

GitHub Releases のボタンは v0.1.0 の成果物公開後に有効になります。公開前にリンクが見つからない場合は、ストア審査とリリース準備の完了をお待ちください。

S-03 · Recipes

実サイト向けレシピ集

実 URL・CSS selector・実サービスのスクリーンショットは載せません。画面が変わっても辿り直しやすい言葉で案内します。

サービスusage ページの辿り方教える対象
ClaudeWeb / Claude Code Claude の Web 版にログインし、アカウント設定からプランや利用状況を確認できる画面へ進みます。 Weekly usage などの％表示、利用済み / 上限、リセット日時。Claude Code と Web が同じ契約枠を使う場合は同じ値を登録します。
Codex CLIChatGPT 契約枠 ChatGPT にログインし、設定から契約プランと利用状況を確認できる画面へ進みます。 5時間枠や週次枠の残量、利用済み / 上限、リセット日時。CLI のローカルログや API 利用額ではなく、契約画面に見える値を選びます。
GrokxAI subscription Grok にログインし、アカウント設定または Subscription から利用状況が見える画面へ進みます。 残クレジット、残メッセージ数、利用済み / 上限、リセット日時。契約プランによって表示される指標が違うため、普段見る値だけで十分です。
GitHub Copilot GitHub の個人設定から Copilot の管理画面へ進みます。組織契約の場合は、組織側の管理画面も確認します。 Premium requests の利用量 / 上限や月次リセット日。個人と組織で表示場所が違う場合は、実際に割り当てられている側を登録します。
Cursor Cursor のアカウントにログインし、設定または Usage から契約状況が見える画面へ進みます。 リクエストやクレジットの利用量 / 上限、残量、リセット日時。プランごとに名称が違っても、数値として見えている箇所を選べます。
Ollamalocal / hosted ローカル実行だけなら共通のサブスク残枠はありません。ホスティングサービスを併用している場合は、その提供元の設定から Usage / Quotas 相当の画面へ進みます。 提供元に表示される GPU 時間、クレジット、リクエスト上限など。ローカル Ollama だけなら登録不要です。
最終確認: 2026-07-16 必要なサービスだけ登録すれば OK。6個すべてを揃える必要はありません。
API 従量課金は対象外です。 Anthropic Console API・OpenAI Platform API・xAI API など、API キーを使う従量課金の残高は扱いません。many-ai-usage は、ログイン後のページに見えているサブスクリプション枠をブラウザ内で読む拡張です。

辿り方が変わっていた

サービス側の画面変更はあり得ます。GitHub Issue で知らせてください。このレシピは年1〜2回を目安に見直します。

ここにないサービス

usage の数値が Web ページに見えていれば、teach-mode で自分用に登録できます。掲載6サービスだけの専用拡張ではありません。

公式サポート一覧ではない

レシピは辿り方の例です。各サービスの運営元との提携や、画面仕様の保証を示すものではありません。

S-04 · FAQ

よくある質問 / 落とし穴

プライバシー、別 PC、画面変更など、最初につまずきやすい点をまとめました。

Q. usage の数字は外部 AI に送られますか？

いいえ。解析はブラウザ内だけで行い、ページ HTML・Cookie・トークンを外部 AI やサーバーへ送りません。専用アカウントやクラウド同期もありません。

Q. 別 PC でも同じ設定を使えますか？

現時点では自動同期しません。クラウドへ送らない設計のため、別 PC では Provider と読み取る値をもう一度登録してください。

Q. サービス側の DOM が変わって読めません

該当タイルまたは Provider 設定の Re-teach から、新しい位置をもう一度クリックしてください。保存済みの値が見つからない場合も再学習できます。

Q. ログインしていなくても読めますか？

いいえ。各サービスの usage ページにはログインが必要です。拡張は今のブラウザセッションで見えるページを読むだけで、代理ログインはしません。

Q. API キー方式の残高も出せますか？

現時点では対象外です。API キーを保存せず、サブスク契約のページに見える残枠だけを扱います。

Q. うまく動きません

まず URL とログイン状態を確認し、Re-teach を試してください。解決しなければ、サービス名・プラン種別・再現手順を添えて GitHub Issue で報告してください。秘密情報が映るスクリーンショットは添付前に隠してください。

まだ解決しない場合: many-ai-usage の GitHub Issues へ。ページ URL、Cookie、API キーなどの秘密情報は投稿しないでください。
