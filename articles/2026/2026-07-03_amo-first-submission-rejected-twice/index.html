初めての Firefox 拡張を AMO に出したら、公開前に 2 回落ちた

コンテナで開いたタブが全部「ホーム / X」で見分けがつかない問題を 95 行の自作拡張で解決し、初めて AMO（addons.mozilla.org）に提出しました。実装より提出でつまずいた話です。2026 年から必須になった data_collection_permissions と、「重複したアドオン ID」という一見意味不明なエラーの正体をまとめました。

この記事のテーマ

AMO の自動検証はローカル開発（about:debugging）では見えない要件を持っています。データを一切収集しない拡張でも「収集しない」という宣言（data_collection_permissions）が必須なこと、検証に失敗したアップロードでも下書きが残り、新規登録からやり直すと自分の下書きと ID 衝突すること。この 2 つを知っていれば、初提出は一発で通ります。ライセンスの表明場所が manifest ではなく提出フォームだけ、という細部も含めて、次に Firefox 拡張を作る人（と自分）向けのチェックリストにしました。
